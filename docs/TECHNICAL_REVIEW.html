CRM Contacts: Technical Review Answers

Concise answers about the implemented architecture, behavior, tests, and current trade-offs.

1. Code structure

ContactsWorkspace owns URL state and wires small components (ContactFilters, ContactsTable, PaginationBar, BulkTagToolbar, Toast), each with its own CSS module. Directory reads live in useContactDirectory and bulk tagging in useBulkTagging. ContactDialog composes field, tag, conflict and activity components, with the save flow in useContactSubmit. Route Handlers validate HTTP input, services compose reads, and repositories own database operations.

2. API and server state

Loading, empty, success, and error states are explicit. Superseded reads are cancelled with AbortController, and the last successful results remain visible during background loading. A custom hook is used instead of TanStack Query because the app has one main directory view; the trade-off is no shared cache, retries, or background refetching.

3. Search, filters, and navigation

Search is debounced by 300 ms. Search, company/tag filters, sorting, and pagination are URL-backed. Filter and sort changes reset the page. Directory reads are paginated on the server.

4. Forms and concurrent updates

Formik manages form state and Zod validates fields on both client and server. Unsaved edits are guarded on close and page unload. Contact and tag mutations compare the supplied version with the stored version and increment it on success. A stale write returns 409 VERSION_CONFLICT with the latest record (duplicates return 409 DUPLICATE_CONTACT, unknown tags 422 INVALID_TAGS, malformed JSON 400 INVALID_JSON); the dialog compares draft and server values and supports accepting latest values or merging only the user's changed fields/tags before retrying.

5. Accessibility and responsive UX

Fields are labelled and connect validation messages with ARIA attributes. The dialog sets and restores focus, traps keyboard focus, and supports Escape. Async feedback uses live status/alert regions. The desktop table becomes contact cards on narrow screens while pagination remains visible.

6. React and code quality

Hooks remain at component top level; fetch effects clean up by aborting requests. Form and query state are controlled, and the directory read logic is not embedded in layout rendering. The implementation avoids global state and additional libraries where the app does not need them.

7. Meaningful tests

Vitest covers unit logic, UI behavior with Testing Library and jsdom (search debounce, filters, pagination, empty and error states, bulk add/replace and partial failure, dialog validation, conflicts, focus and Escape), and API routes against a real database (validation, invalid JSON, duplicates, version conflicts, invalid tags, concurrent updates). CI runs lint, typecheck, both test suites and the build.

8. Performance and maintainability

Server pagination, relevant database indexes, debounce, and request cancellation keep work bounded. Virtualization and prefetching are unnecessary for the current page size. Known gaps include no authentication/authorization, offline queue, real-time updates, tag CRUD, or contact deletion. Bulk tag updates support add and replace modes, are sequential, and report partial progress if one fails. Search uses ILIKE '%…%', which a trigram index would speed up at scale.
